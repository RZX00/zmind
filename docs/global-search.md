# 全局搜索（跨画布节点检索）方案

状态: Draft

## 目标与价值
- 一次输入，跨画布找到任何卡片节点
- 帮用户快速找回记录，建立知识连接
- 结果一键直达，减少来回翻找的认知负担
- 全程非技术表达，避免暴露实现细节

## 范围与约束
- 仅搜索当前登录用户权限内的画布（账号边界）
- 只搜索“当前画布版本”，不搜历史版本
- 回收站/已删除画布不参与搜索
- 归档画布默认不搜，可手动开启
- 结果粒度为“节点”，不是画布
- 不搜 OCR、音视频正文、系统元数据、连接线

## Phase 1: 可行性与数据结构分析（架构视角）

### 现有数据结构（核心事实）
- 画布存储在 `public.canvases`，内容在 `doc` JSONB
- `doc.nodes[]` 为节点数组，节点字段包含:
  - id, type, content, x, y, width, height
  - table: data.rows
  - media: fileName, externalUrl
  - canvas-link: title, content, targetCanvasId
  - code: content
- 文件夹层级在 `folders` 表，画布所属通过 `doc.folderId`

### JSONB 直接检索的现实问题
- JSONB 适合结构过滤，不适合大规模全文检索
- 对 `doc` 进行 `jsonb` 扫描，无法有效利用排名/模糊匹配
- 即使建立 GIN，也只能对结构索引，无法对多字段自然排序
- 当用户有上千节点时，纯 JSONB 扫描会导致延迟明显上升

### 方案对比

方案 A: Postgres 原生全文检索 + 节点索引表（推荐 MVP）
- 设计: 把节点拆成“可搜索行”，单独建索引表
- 能力: tsvector + trigram，兼顾中文和模糊匹配
- 代价: 需要维护索引同步，但运维成本低
- 结论: 初期规模最稳、最快落地

方案 B: 独立搜索引擎（Meilisearch/Elastic）
- 设计: 将节点推送到搜索引擎，支持更复杂的权重/语义
- 能力: 多字段权重、拼写纠错、同义词扩展、统计分析
- 代价: 同步链路复杂、成本上升、故障面增加
- 结论: 当节点量达到百万级或需要强语义能力时再引入

### 性能瓶颈与风险评估
- 保存画布时重建索引: 大画布 JSON 解析成本高
- 高并发查询: 频繁输入触发查询，需要节流和分页
- 高亮片段计算: 运行时切片会增加 CPU 消耗
- 权限变更: 索引可能短暂滞后，需要 RLS 再兜底

### 初期规模判断
- 1 个用户 50 画布 * 200 节点 = 1 万节点
- Postgres FTS + GIN 足够支撑，典型延迟 < 100ms
- 中期可加缓存和“最近搜索”避免重复查询

### 结论（架构建议）
- MVP 用 Postgres 索引表（节点级）
- 预留升级到外部搜索引擎的接口与数据同步点

## Phase 2: 产品方案设计（PM 视角）

### UX 审计（按 3 步走）

Step 1: 诊断（直说问题）
- 只在单画布内搜索 = 认知断裂，用户会丢失线索
- 让用户点“搜索/生成”按钮 = 多余步骤
- 暴露技术字段/ID = 噪音，用户不理解也不需要
- 搜不到时只给空白 = 让用户怀疑是不是没保存

Step 2: To-C 重构（设计逻辑）
- 入口要全局，任何页面都能一键到达
- 输入即搜索，结果先出现，不需要“确认”按钮
- 过滤器隐藏在“筛选”里，只在需要时出现
- 结果行要提供上下文，避免“看见但不知道在哪”

Step 3: 解决方案（不写代码）
- 打开方式: 顶栏搜索框 + Cmd/Ctrl+K
- 搜索面板: 输入框在顶，结果列表在下
- 行为: 实时搜索 + 键盘上下选择 + 回车跳转

### 交互入口
- 桌面端: 顶栏常驻搜索框
- 快捷键: Cmd/Ctrl+K 打开全局搜索
- 移动端: Header 里的搜索图标

### 搜索行为
- 150-250ms 防抖
- 最小长度: 中文 1 字符，英文 2 字符
- 空输入显示“最近更新”节点列表
- 无“搜索按钮”，输入即结果

### 结果呈现
每条结果必须包含:
- 节点类型图标
- 命中高亮片段（最多 2 段、每段 120 字符内）
- 所属画布名称 + 文件夹路径
- 更新时间（相对时间）

### 排序与高亮
- 主排序: 内容相关性
- 次排序: 最近更新（轻权重）
- 权重顺序: 首行/标题 > 正文 > 表格单元 > 文件名
- 画布标题仅用于上下文，不参与主要相关性

空结果文案:
- “没有找到与「xxx」相关的内容”
- 建议: “试试更短的词，或换一个关键词”

异常文案:
- “搜索暂时不可用，请稍后再试”

### 跳转与定位
- 点击结果即打开画布并定位到节点
- 视口居中 + 高亮 2-3 秒（脉冲边框）
- 如果节点不存在: 提示“这个节点可能已被删除”并保持搜索面板

### 过滤器（默认隐藏）
- 仅当前画布
- 包含归档画布（默认关闭）

### 关键决策与边缘情况
已确定
- 不搜删除/回收站
- 只搜当前版本
- 归档默认不搜，可选开启
- 需要“仅当前画布”过滤器
- 空查询显示“最近更新”

需要产品层面的持续关注
- 协作画布: 默认参与（只要有权限）
- 权限变更: 结果允许短暂不一致，但点击必须兜底
- 节点被合并/删除: 友好提示，避免跳转失败
- 大表格内容: 只索引前 N 行，避免噪音

## Phase 3: 技术实现路线图（Tech Lead 视角）

### 后端路线
1) 构建节点索引表
- 字段: account_id, canvas_id, node_id, node_type, search_text, preview_text
- 维护 tsvector + trigram 索引

2) 索引构建策略
- 保存画布时重建该画布索引
- 后台任务支持批量回填与修复
- 对删除/回收站画布直接跳过

3) 搜索 API
- POST /api/search/nodes
- 参数: query, limit, cursor, scope, canvas_ids, folder_ids, node_types, include_archived
- 空 query 返回最近更新

4) 权限与安全
- 账号级别 RLS 兜底
- 搜索结果必须在用户可访问范围内

### 前端路线
1) 搜索面板组件
- 输入框 + 结果列表 + 过滤器入口
- 支持键盘导航与 Esc 关闭

2) 结果跳转
- 选中后打开画布并定位到节点
- 触发高亮反馈，建立“已找到”确认感

3) 体验优化
- 查询节流与最小字符限制
- 保留最后一次搜索结果直到面板关闭

### 里程碑
- M0: 索引表与回填脚本
- M1: 搜索 API 与权限限制
- M2: 前端搜索面板与跳转
- M3: 排序优化（权重/拼写纠错）
- M4: 规模化时接入搜索引擎

## 可执行任务清单（M0-M2）

### M0: 索引与数据准备
- 明确节点文本拼接规则（不同节点类型的可搜索字段）
- 定义 preview_text 生成规则与长度上限
- 定义表格内容截断策略（行/列上限）
- 设计回填策略（全量、按画布、按空间）
- 明确归档/删除画布的过滤规则
- 设计索引一致性策略（保存触发 + 异步修复）
- 输出: 数据字典 + 回填计划 + 风险清单

### M1: 搜索 API 设计
- 统一请求结构（query、scope、filters、cursor）
- 定义空 query 返回逻辑（最近更新）
- 定义排序权重与高亮范围格式
- 定义错误码与文案映射表
- 设计限流与最小字符策略
- 输出: API 规格 + 示例请求/响应

### M2: 前端搜索体验
- 搜索入口设计（顶栏 + 快捷键 + 移动入口）
- 搜索面板结构（输入 + 结果 + 筛选）
- 键盘导航（上下/回车/ESC）
- 结果跳转与定位反馈（居中 + 高亮）
- 空态/错误态/无权限态提示
- 输出: 交互流程图 + 文案清单

## 交互流程与文案清单（M2）

### 打开与输入
- 行为: Cmd/Ctrl+K 打开搜索面板
- 文案: 输入框占位 “搜索所有画布…”

### 实时结果
- 行为: 输入后 150-250ms 刷新结果
- 文案: 列表标题 “搜索结果”

### 空输入（最近更新）
- 行为: 输入为空时展示最近更新节点
- 文案: 列表标题 “最近更新”

### 无结果
- 行为: 不匹配时显示空态
- 文案: “没有找到与「xxx」相关的内容”
- 文案: “试试更短的词，或换一个关键词”

### 错误态
- 行为: 搜索失败或服务不可用
- 文案: “搜索暂时不可用，请稍后再试”

### 结果点击
- 行为: 打开画布并定位到节点
- 文案: 无额外弹窗，直接跳转

### 节点缺失
- 行为: 节点不存在时不跳转
- 文案: “这个节点可能已被删除”

### 过滤器入口（默认隐藏）
- 行为: 点击筛选按钮展开
- 文案: 按钮 “筛选”
- 选项: “仅当前画布”
- 选项: “包含归档画布”

## 技术实施拆解（M0-M2）

### 后端任务（执行清单）
- 数据结构: 节点索引表 + 必要字段（账号/画布/节点/位置/更新时间/搜索文本）
- 索引: tsvector + trigram 的组合索引
- 归档字段: 画布表增加归档标记与时间戳
- 索引构建: 画布保存触发重建；删除/归档时清理或失效
- 回填脚本: 支持按画布/按空间/全量
- 搜索 RPC: 支持 scope、过滤器、分页、空 query 最近更新
- 高亮策略: 返回 range 结构而非 HTML
- 权限兜底: account_id 过滤 + RLS
- 运行监控: 搜索耗时、命中率、错误率

### 前端任务（执行清单）
- 搜索面板: 输入 + 结果列表 + 筛选按钮
- 快捷键: Cmd/Ctrl+K 打开与焦点管理
- 查询策略: 防抖 + 最小字符 + 空 query 最近更新
- 结果渲染: 高亮片段、画布标题、路径、时间、节点图标
- 结果跳转: 打开画布 + 视口居中 + 高亮反馈
- 失败兜底: 无结果/错误态/节点缺失提示
- 状态保持: 面板关闭前保留结果与筛选条件

### 依赖与顺序
- M0 -> M1: 先有索引表与回填，API 才能稳定工作
- M1 -> M2: API 稳定后再做前端体验
- 紧急兜底: 若索引未就绪，前端展示“搜索暂不可用”

### 成功指标（上线初期）
- 搜索 P95 延迟 < 200ms（不含网络）
- 结果点击成功率 > 99%
- “无结果”后再次搜索的二次转化率可追踪

## 验收标准
1) 用户在任意页面可一键打开搜索
2) 结果仅来自当前账号范围
3) 删除/回收站内容不会出现
4) 归档内容默认隐藏，可手动开启
5) 点击结果能跳转并定位到节点
6) 空查询会展示最近更新
