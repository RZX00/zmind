# PRD - 信息架构与命名统一（IA & Naming Unification）

## 1. 背景与问题（直指痛点）
- 用户界面暴露“thread/agent/project”等工程词，造成理解断层。
- 导航重复与混乱：Dashboard/Workspace/Projects/Threads 并行存在。
- 新手不知道“从哪里开始”，入口过多且语义冲突。

## 2. 目标与非目标
**目标**
- 统一命名体系，让用户只认“画布/工作区/AI助手”。
- 清理导航层级，降低入口噪音。
- 文案与路径一致，减少认知负担。

**非目标**
- 不改后端数据结构。
- 不改计费规则与权限模型。
- 不做完整视觉重构（仅文本与信息结构）。

## 3. 命名规范（对用户）
- **画布**：唯一主载体，替代“线程/项目”对外呈现。
- **对话**：仅在 AI 面板内部出现（弱化）。
- **AI 助手**：替代“Agent”。
- **模型**：可保留，但只能出现在“AI 助手设置”内。
- **工作区**：替代 Dashboard/Workspace/Projects。
- **文件夹/集合**：统一称谓，不混用。

## 4. 信息架构（目标态）
```
顶层导航
 - 工作区
 - 知识库
 - 探索（模板）
 - 垃圾箱
 - 设置
```

**入口统一**
- 所有画布入口集中在“工作区”。
- 分享入口只保留在画布顶栏与卡片菜单。
- “线程页”对外隐藏，仅保留必要重定向。

## 5. 术语映射表
| 旧术语 | 新术语 | 对用户是否显示 |
| --- | --- | --- |
| Thread | 对话 | 仅 AI 面板 |
| Project | 文件夹/集合 | 是 |
| Agent | AI 助手 | 是 |
| Model | 模型 | 仅 AI 设置 |
| Dashboard | 工作区 | 是 |

## 6. 路由与兼容策略
- 旧路径保留重定向（例如 `/dashboard` -> `/workspace` 逻辑层统一）。
- 分享链接旧结构继续可访问，但 UI 展示新命名。
- 对外 UI 不再出现“thread/project/agent”字样。

## 7. 文案更新范围
- 导航与侧边栏菜单
- 空状态与引导文案
- 分享/权限/错误提示
- 订阅与计费入口文案
- 帮助与提示文案

## 8. 体验流程（低保真）
**导航结构**
```
[团队切换]
   |
   +-- 工作区
   |     +-- 画布列表
   |     +-- 文件夹
   |
   +-- 知识库
   +-- 探索（模板）
   +-- 垃圾箱
   +-- 设置
```

**空状态（工作区）**
```
┌───────────────────────────────┐
│ 这里还没有画布                 │
│ [创建新画布]                   │
│ 小提示：你也可以先描述需求…     │
└───────────────────────────────┘
```

## 9. 埋点与指标
- `workspace_entered`
- `canvas_created`
- `ai_assistant_opened`
- `navigation_item_clicked`

**成功指标**
- 新手完成首个画布时间下降
- 导航误点率下降
- 术语相关客服问题下降

## 10. 开放问题
- “探索”是否改为“模板”？
- “知识库”是否改为“资料库”？
- 文件夹统一命名是“文件夹”还是“集合”？
- “对话”是否完全隐藏为“AI 助手记录”？
