# Zmind 前端自部署全流程指南

本文档面向需要在自有服务器上部署 Zmind 前端的同学，覆盖环境准备、构建与上线步骤，并说明从测试/预发布切换到生产环境时需要调整的关键配置。请将此流程作为团队内部的标准操作手册。

---

## 1. 前置条件

| 项目 | 说明 |
| --- | --- |
| 操作系统 | Linux 服务器（例如阿里云 Linux，已安装 One Panel） |
| 访问权限 | 拥有该服务器的 SSH / One Panel 终端权限及 sudo 能力 |
| 基础组件 | Docker 与 Docker Compose（One Panel 默认已安装） |
| 可选工具 | 若需手动构建，请安装 Node.js ≥ 20 与 npm ≥ 10 |
| 域名与证书 | 已在域名服务商（例如 Namecheap）完成 DNS 解析到服务器，准备好正式证书（PositiveSSL 或 Let’s Encrypt） |

## 2. 准备环境变量

前端依赖 `frontend/.env.local`。部署前请根据环境填写：

```dotenv
NEXT_PUBLIC_BACKEND_URL=https://zmind.so/backend/api
NEXT_PUBLIC_URL=http://zmind.so

# Supabase 客户端配置（需与后端保持一致）
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=public-anon-key

# 如需启用埋点等服务，可在此追加
# NEXT_PUBLIC_POSTHOG_KEY=xxxxx
```

> **区分测试与生产**  
> - 预发布/测试环境：`NEXT_PUBLIC_BACKEND_URL`、`NEXT_PUBLIC_APP_URL` 指向测试用域名。  
> - 正式环境：将两项改为正式域名及后端地址，证书也应覆盖这些域名。
>
> 请勿在前端 `.env.local` 中写入任何服务端密钥。后端私钥保存在 `backend/.env`。

## 3. 构建流程

### 3.1 使用 Docker（推荐）

在仓库根目录执行：

```bash
docker compose build frontend
```

如需强制拉取最新依赖：

```bash
docker compose build --no-cache --pull frontend
```

镜像构建完成后，容器内部会完成 `next build`，输出的生产包监听在 `3000` 端口。

### 3.2 手动构建（备用）

```bash
cd frontend
npm install --legacy-peer-deps
npm run build
npm run start -- --hostname 0.0.0.0 --port 3000
```

若走手动方式，请使用 PM2 / systemd 等工具常驻进程，并自行处理环境变量。

## 4. 启动服务

```bash
# 后台启动前端容器
docker compose up -d frontend

# 可选：同时启动后端、Worker、Redis
docker compose up -d frontend backend worker redis
```

docker compose build --pull frontend backend worker 

默认情况下，前端容器暴露 `3000` 端口。通过 Docker 网络，它可被反向代理程序（如 One Panel 中的 Nginx）访问。

### 4.1 One Panel / Nginx 反向代理配置

1. 在 One Panel 中新增站点：域名填写 `zmind.so`。  
2. 反向代理地址指向 `http://frontend:3000`（Docker Compose 默认服务名）。  
3. 上传证书文件（`.crt`、`.key`、`ca-bundle`），并开启强制 HTTPS。

示例 Nginx 片段：

```nginx
server {
    listen 443 ssl;
    server_name zmind.so;

    ssl_certificate     /etc/nginx/certs/zmind.so.crt;
    ssl_certificate_key /etc/nginx/certs/zmind.so.key;
    ssl_trusted_certificate /etc/nginx/certs/zmind.so-ca-bundle.crt;

    location / {
        proxy_pass http://frontend:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 5. 上线流程（生产环境）

1. **同步最新代码**
   ```bash
   git pull origin main
   ```
2. **构建镜像**
   ```bash
   docker compose build --pull frontend
   ```
3. **更新容器**
   ```bash
   docker compose up -d --no-deps frontend
   ```
4. **检查日志与健康状态**
   ```bash
   docker compose logs -f frontend
   curl -I https://zmind.so
   ```

## 6. 测试环境 → 生产环境配置差异

| 配置项 | 测试环境示例 | 生产环境示例 |
| --- | --- | --- |
| `NEXT_PUBLIC_BACKEND_URL` | `https://staging-api.zmind.so` | `https://api.zmind.so` |
| `NEXT_PUBLIC_APP_URL` | `https://staging.zmind.so` | `https://zmind.so` |
| 证书 | 测试域名证书（可自签） | 正式域名的可信证书 |
| Nginx 反代地址 | 指向测试容器 | 指向生产容器 |
| Docker 镜像标签（可选） | `frontend:staging` | `frontend:latest` |

上线前请确认前后端的 `.env` 均切换为正式配置，必要时更新 CDN / WAF / 监控项。

## 7. 回归验证清单

- `https://zmind.so` 能正常访问，浏览器无证书警告。
- 浏览器网络面板中，接口请求 `https://api.zmind.so` 返回 200。
- 静态资源（JS/CSS/图片）加载成功，Chrome 控制台无 `ReferenceError` / HMR 报错。
- Supabase 登录流程可用，邀请链接可正确生成（`NEXT_PUBLIC_APP_URL` 必须正确）。
- 使用 `npm run build && npm run start` 本地演练，确保无构建错误。

## 8. 常见问题

| 问题 | 解决办法 |
| --- | --- |
| Docker 构建卡在 `npm ci` | 检查服务器是否限制外网访问；如需代理，设置 `NPM_REGISTRY` 环境变量或 `.npmrc`。 |
| HTTPS 访问提示自签名证书 | 在服务器正确安装正式证书并配置 Nginx `ssl_trusted_certificate`。 |
| 前端空白页 / chunk 加载失败 | 清理 `.next/` 后重新构建；确认无循环依赖导致的编译报错。 |
| Supabase 登录失败 | 检查 `NEXT_PUBLIC_SUPABASE_URL` 与 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 是否与后端一致。 |

## 9. 后续建议

- 接入 CI/CD：例如 GitHub Actions 构建并推送镜像到镜像仓库。
- 按环境拆分 Compose 文件，使用 `docker compose -f docker-compose.yaml -f docker-compose.prod.yaml`。
- 配置监控与告警（站点可用性、异常流量等）。
- 日志集中化：考虑把容器日志同步到 ELK / Loki。
