⑦ 第一个 PR 为何是"脑"不是"眼"(批判修正)

⚠ 对抗 agent 驳回了 workflow 自己的推荐

规划综合本来推荐"空间读取器先行"。批判驳回:那是 AI 有眼睛没脑子——一个没人读的读取器,和一个没人写的槽一样惰性,等于你否决的"slots-first"痛根换皮。 第一个落地的增量必须让 AI 真的"做点用户能接受的事"。

✓ 采纳:先建脑的确定性核心

PR #2 = 诊断 + 建议模型:"找问题 → 提议修复"——这是真正的 AI-first 能力(用户接受/忽略),无需 LLM、纯 Python、离线可单测、对原生 lane 零回归,正是 LLM 循环 + 接线要消费的地基。比"全 stub 端到端循环"更小更稳(不碰 jwt 污染层),又比"空间读取器"更 AI-first(是脑不是眼)。已落地。

⑧ 关键护栏 / 待决

  • 角色 AI-派生-only:存 provenance/metadata,永不用户可编辑字段,否则 IBIS 重生。(已在 PR #2 钉死)
  • per-batch derivation id:reject-by-derivation 须 per-batch(非 per-run),否则一次撤销误删无关提议。(PR #2 已用 batchId)
