## 1. 执行机制

```txt
需求/风险 -> Epic/Story拆解 -> 当周实现 -> 自动化验证 -> 灰度/发布 -> 复盘 -> 下一周
```

执行原则：
1. 每周至少交付 1 个“可上线”的主链路改动。
2. 每个改动必须有：监控点、回滚开关、验证步骤。
3. 不做“大爆炸重构”，只做连续收敛。

## 5. 当前冲刺（W1）执行清单

### W1-01 编排闭环（必须）
- 目标：`outbox relay` 与 `projection worker` 加入默认编排并可观察。
- 产出：
  - 更新 `docker-compose.yaml`
  - 更新 `backend/docker-compose.yml`
  - 增加健康检查与日志约定
- DoD：
  - `docker compose up` 后可看到两个 worker 稳定运行
  - worker 停止后自动拉起
- 状态：已完成（`docker-compose.yaml`、`backend/docker-compose.yml`）

### W1-02 写路径可观测基线（必须）
- 目标：Canvas 写入日志可区分 realtime / legacy。
- 产出：关键入口日志统一字段（request_id, path_source, canvas_id）。
- DoD：可按 path_source 聚合统计。
- 状态：已完成（`canvas_command_application_service.py` 写路径日志）

### W1-03 验证脚本与验收记录（必须）
- 目标：固定化验收流程，避免口头确认。
- 产出：
  - 验证命令列表
  - 验证结果记录模板
- DoD：任何人可按文档复现验证。
- 状态：已完成（`docs/reports/2026-02-27-w1-verification-checklist.md`）
